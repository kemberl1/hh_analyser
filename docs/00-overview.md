# 00 — Обзор продукта (Product Overview)

> **Статус документа:** Phase 0 (спецификация). Источник истины для последующих фаз реализации.
> **Язык:** русский; технические термины и названия библиотек — в оригинале.

---

## 1. Краткое описание продукта

**HH Analyser** — web-приложение для сбора и анализа статистики IT-вакансий с площадки [hh.ru](https://hh.ru). Приложение в автоматическом режиме (ежедневно по расписанию) собирает данные о вакансиях, нормализует их и сохраняет в базу данных, после чего предоставляет пользователю **дашборды, инфографику и статистику** для анализа рынка труда «почти в реальном времени».

Ключевая ценность для пользователя (соискателя): получить объективную, агрегированную картину рынка по своей специальности — сколько платят, какие навыки востребованы по грейдам, кто нанимает, как меняется спрос во времени.

## 2. Цели продукта

| # | Цель | Измеримый результат |
|---|------|---------------------|
| G1 | Автоматизированный сбор вакансий с hh.ru | Ежедневный CRON-сбор без ручного вмешательства |
| G2 | Достоверная агрегированная статистика по зарплатам и навыкам | Метрики считаются по дате публикации `published_at`, мультивалютность и gross/net учтены |
| G3 | Наглядная визуализация рынка | Дашборды с фильтрами по периодам и грейдам |
| G4 | Расширяемость под AI-фичи | Архитектура готова к LLM-анализу рынка и анализу резюме |
| G5 | Итеративная поставка | Каждая фаза независимо проверяема (есть Definition of Done) |

## 3. Целевая аудитория

- **Основной пользователь:** IT-соискатель (Frontend-разработчик), который хочет понять рынок, оценить свою зарплатную вилку и определить, какие навыки «подтянуть».
- **Вторичный пользователь:** аналитик / рекрутер, изучающий рынок труда.

## 4. Scope MVP

### 4.1. Входит в MVP

- Специальность: **только Frontend** с разбивкой по грейдам **Junior / Middle / Senior**.
- Источник данных: **только hh.ru** (**основной путь — HTML-парсинг** страниц поиска и вакансий; фолбэк — публичный `api.hh.ru` по флагу/при доступности, т.к. на момент Phase 2 API недоступен).
- Регион: **вся Россия**.
- Ежедневный автоматический сбор и актуализация статистики (CRON).
- Учёт по дате **публикации** вакансии (`published_at`), а не по дате парсинга.
- Идемпотентный сбор (повторный парсинг не создаёт дубликатов; dedup по `hh_vacancy_id`).
- **Фильтрация релевантности (Relevance Filtering):** нерелевантные вакансии (Fullstack, Backend, руководитель проектов, QA и т.п.) отсеиваются и не попадают в БД; словари ключевых/стоп-слов конфигурируемы.
- Метрики: зарплаты (медиана, min, max, перцентили, мультивалютность, gross/net, «от/до», отсутствие зарплаты), рейтинг навыков по грейдам, анализ работодателей, динамика во времени, фильтры день/неделя/месяц/год + дополнительные продуктовые метрики (см. [`04-metrics.md`](04-metrics.md)).
- REST API + Frontend-дашборды.

### 4.2. НЕ входит в MVP (вынесено в поздние фазы)

- LLM-анализ рынка по специальности — **Phase 6**.
- Умный анализатор резюме (оценка «профпригодности», прохождение фильтров по ключевым словам) — **Phase 7**.
- Другие специальности кроме Frontend, другие источники кроме hh.ru, другие регионы.
- Аутентификация пользователей, личные кабинеты, платные тарифы (могут появиться позже).

## 5. Утверждённые решения по стеку

> Зафиксированы заказчиком. Не подлежат изменению; допускается уточнение версий и конкретных библиотек (см. [`05-tech-stack.md`](05-tech-stack.md)).

- **Backend:** FastAPI (Python) + PostgreSQL + Alembic.
- **Frontend:** React + Vite.
- **Парсинг:** **основной путь — HTML-парсинг** страниц hh.ru; фолбэк — публичные ручки `api.hh.ru` (включается по флагу/при доступности; на момент Phase 2 API недоступен).
- **LLM-провайдер:** X5 CoPilot API 2.0 (OpenAI-совместимый), ключ в `.env` → `API_KEY` (детали см. ниже и в [`05-tech-stack.md`](05-tech-stack.md)).

## 6. Методология

Итеративная разработка: один кусок функциональности → проверка (Definition of Done) → следующий. Дорожная карта разбита на независимо проверяемые фазы (см. [`07-roadmap.md`](07-roadmap.md)).

## 7. Глоссарий (Glossary)

| Термин | Определение |
|--------|-------------|
| **Вакансия (vacancy)** | Объявление о найме на hh.ru. Идентифицируется глобальным `hh_vacancy_id`. |
| **Грейд (grade)** | Уровень позиции: Junior / Middle / Senior. Определяется по полю опыта hh.ru и эвристикам по названию/описанию **после прохождения фильтра релевантности**. |
| **Relevance Filtering (фильтрация релевантности)** | Шаг пайплайна между parse и upsert: rule-based классификация вакансии «релевантно Frontend / мусор» по конфигурируемым словарям положительных и стоп-сигналов. Нерелевантные не сохраняются. |
| **Скилл / навык (skill)** | Ключевой навык, ожидаемый от соискателя (`key_skills` в API hh.ru + извлечённые из описания). |
| **Работодатель (employer)** | Компания, опубликовавшая вакансию (`employer` в API hh.ru). |
| **`published_at`** | Дата/время **публикации** вакансии на hh.ru. Базовая ось времени для всех метрик. |
| **`parsed_at` / `collected_at`** | Момент, когда наш парсер получил/обновил запись. Технический атрибут, не используется для статистики. |
| **gross / net** | Зарплата «до вычета налогов» (gross) или «на руки» (net). На hh.ru — флаг `salary.gross`. |
| **Мультивалютность** | Зарплаты могут быть в RUB / USD / EUR и др. Для сравнения приводятся к базовой валюте (RUB) по курсу. |
| **Snapshot / aggregation** | Предрассчитанная агрегированная метрика за период (для быстрых дашбордов). |
| **Идемпотентность парсинга** | Повторный сбор тех же вакансий не создаёт дубликатов и корректно обновляет существующие записи (upsert по `hh_vacancy_id`). |
| **Rate-limiting / вежливый краулинг** | Ограничение частоты запросов к hh.ru (RPS, задержки, User-Agent, ретраи) во избежание блокировок и нарушения ToS. Особенно важно для HTML-парсинга как основного пути. |
| **LLM-adapter** | Абстрактный слой доступа к LLM, скрывающий конкретного провайдера (X5 CoPilot API). |
| **DoD (Definition of Done)** | Критерии приёмки фазы. |
