# 04 — Каталог метрик (Metrics Catalog)

> Все метрики считаются по дате **публикации** `published_at` (FR-11).
> Периоды фильтрации: **день / неделя / месяц / год** (FR-21).
> Результаты предрассчитываются в `snapshots` (см. [`03-data-model.md`](03-data-model.md)).

---

## 1. Базовые понятия и предобработка

### 1.1. Периоды (period bucketing)

| `period_type` | Бакет (период) | Ключ `period_start` |
|---------------|----------------|---------------------|
| `day` | календарный день | дата дня |
| `week` | ISO-неделя (Пн–Вс) | дата понедельника |
| `month` | календарный месяц | первое число месяца |
| `year` | календарный год | 1 января |

Вакансия попадает в бакет по своему `published_at` (в часовом поясе `Europe/Moscow`). Для диапазонных запросов API период задаётся `date_from`/`date_to` либо пресетом.

### 1.2. Срезы (dimensions)

- **Грейд:** Junior / Middle / Senior / (все).
- **Валюта базиса:** по умолчанию RUB (приведённая).
- **Базис gross/net:** по умолчанию net.

### 1.3. Определение грейда (grade resolution)

Гибридная эвристика (детерминированная, тестируемая):

1. **По полю опыта hh.ru** (`experience.id`):
   - `noExperience`, `between1And3` (нижняя часть) → склонность к **Junior**;
   - `between1And3` → **Middle**;
   - `between3And6`, `moreThan6` → **Senior**.
2. **По названию/описанию** (нормализованный текст): ключевые слова `junior/младший/стажер`, `middle/мидл`, `senior/ведущий/lead`.
3. **Разрешение конфликтов:** приоритет явному указанию в названии; при отсутствии сигналов — `unknown` (учитывается отдельно, не искажает грейдовые метрики).

> Точные правила и веса фиксируются на Phase 2 и покрываются юнит-тестами; настройки выносятся в конфиг.

### 1.4. Нормализация зарплаты (salary normalization)

Исходные поля hh.ru: `salary.from`, `salary.to`, `salary.currency`, `salary.gross`.

**Шаг 1 — валюта → RUB:**

```
amount_rub = amount * rate_to_rub(currency, published_at_date)
```

где `rate_to_rub` берётся из `currency_rates` на дату публикации (A2; при отсутствии — ближайший доступный курс).

**Шаг 2 — gross → net** (приведение к единому базису, по умолчанию net):

```
если gross == true:  amount_net = amount_gross * (1 - NDFL)
если gross == false: amount_net = amount
если gross == NULL:  считаем как gross (консервативно) ИЛИ помечаем флагом assumption
```

`NDFL` — настраиваемый коэффициент (по умолчанию 0.13). Базис (net/gross) — параметр запроса; снапшоты хранятся для net-базиса, gross — вычислимо.

**Шаг 3 — точечная оценка (`point_estimate`)** для метрик из вилки «от/до»:

| Случай | `point_estimate` |
|--------|------------------|
| есть `from` и `to` | `(from + to) / 2` (среднее вилки) |
| только `from` | `from` |
| только `to` | `to` |
| нет ни `from`, ни `to` | вакансия **без зарплаты** → исключается из зарплатных метрик |

Все три значения (`amount_from_rub_net`, `amount_to_rub_net`, `point_estimate_rub_net`) сохраняются в `salaries`.

### 1.5. Обработка вакансий без зарплаты

- Исключаются из расчёта зарплатных метрик (медиана, перцентили и т.д.).
- Учитываются в `total_count` и в доле `salary_disclosure_rate` (см. M1.7).

## 2. Метрики

### Группа M1 — Зарплаты (`metric_type = salary`)

Множество `X` = `point_estimate_rub_net` всех вакансий периода/среза с указанной зарплатой.

| ID | Метрика | Формула / описание |
|----|---------|--------------------|
| M1.1 | **Медиана** | `median(X)` = перцентиль 50 |
| M1.2 | **Минимум** | `min(X)` (с защитой от выбросов — см. ниже) |
| M1.3 | **Максимум** | `max(X)` |
| M1.4 | **Среднее** | `mean(X)` |
| M1.5 | **Перцентили** | p10, p25, p50, p75, p90 — линейная интерполяция |
| M1.6 | **Размах вилок** | средние `amount_from` и `amount_to` по периоду (нижняя/верхняя граница рынка) |
| M1.7 | **Salary disclosure rate** | `доля вакансий с указанной зарплатой = count(with_salary) / total_count` |
| M1.8 | **Распределение (гистограмма)** | частоты по бинам зарплат (для box/violin/гистограммы) |

**Защита от выбросов (для min/max и отображения):** опционально усечение по [p1, p99] или IQR-фильтр (`Q1 - 1.5*IQR`, `Q3 + 1.5*IQR`). Сырые min/max также доступны.

Перцентиль (линейная интерполяция), реализация — `numpy.percentile` / SQL `percentile_cont`:

```
rank = p/100 * (n - 1)
percentile = X_sorted[floor(rank)] + (rank - floor(rank)) * (X_sorted[ceil(rank)] - X_sorted[floor(rank)])
```

### Группа M2 — Навыки (`metric_type = skills`)

Для каждого грейда и периода считается частота навыков по `vacancy_skills`.

| ID | Метрика | Формула / описание |
|----|---------|--------------------|
| M2.1 | **Топ-N навыков** | сортировка по `count` навыка среди вакансий среза |
| M2.2 | **Доля навыка** | `skill_share = vacancies_with_skill / vacancies_in_slice` |
| M2.3 | **Навыки по грейдам** | отдельные рейтинги для Junior / Middle / Senior |
| M2.4 | **Дельта спроса на навык** | изменение `count`/`share` навыка относительно прошлого периода |

### Группа M3 — Работодатели (`metric_type = employers`)

| ID | Метрика | Формула / описание |
|----|---------|--------------------|
| M3.1 | **Топ работодателей** | по числу опубликованных вакансий за период |
| M3.2 | **Доля работодателя** | `employer_vacancies / total_vacancies` |
| M3.3 | **Концентрация рынка** | доля топ-10 работодателей в общем числе вакансий (индикатор концентрации) |

### Группа M4 — Динамика во времени (`metric_type = demand_trend`)

| ID | Метрика | Формула / описание |
|----|---------|--------------------|
| M4.1 | **Кол-во вакансий по периодам** | временной ряд `count` по бакетам |
| M4.2 | **Медианная зарплата по периодам** | временной ряд `median(X)` по бакетам |
| M4.3 | **Рост/падение спроса** | `growth = (count_t - count_(t-1)) / count_(t-1)` (period-over-period) |
| M4.4 | **Скользящее среднее** | сглаживание ряда (напр. 7-дневное MA) для трендов |

### Группа M5 — Дополнительные продуктовые метрики

| ID | Метрика (`metric_type`) | Формула / описание |
|----|--------------------------|--------------------|
| M5.1 | **Распределение по грейдам** (`grade_distribution`) | доли Junior/Middle/Senior среди вакансий периода |
| M5.2 | **Распределение по формату работы** (`format_distribution`) | доли office/remote/hybrid |
| M5.3 | **Распределение по опыту** | доли по `experience_raw` |
| M5.4 | **Топ-связки навыков** (`skill_cooccurrence`) | пары навыков, встречающиеся вместе: `count(skill_a AND skill_b)`; топ по совстречаемости |
| M5.5 | **Зарплатная премия за грейд** | `median(Senior) / median(Junior)` — «стоимость роста» |
| M5.6 | **Премия за навык** | разница медиан зарплат вакансий с навыком и без него (где данных достаточно) |
| M5.7 | **Remote-премия** | разница медиан зарплат remote vs office |
| M5.8 | **Свежесть данных** | `время с последнего успешного прогона` (операционная метрика) |

## 3. Связь метрик со срезами и периодами

```mermaid
flowchart LR
    V[Вакансии с published_at] --> B[Бакетирование по period_type]
    B --> D[Срез по grade currency gross net]
    D --> C[Расчёт метрик M1 to M5]
    C --> SNAP[(snapshots payload jsonb)]
    SNAP --> API[API отдаёт по фильтрам]
```

- Снапшоты считаются по комбинации `metric_type × period_type × period_start × grade × currency × gross_basis`.
- API не пересчитывает на лету: выбирает готовые снапшоты по фильтрам (NFR-1, NFR-2).
- Для произвольных диапазонов (`date_from`/`date_to`) API агрегирует дневные снапшоты в нужный период.

## 4. Краевые случаи и правила качества данных

| Случай | Поведение |
|--------|-----------|
| Вакансия без зарплаты | исключается из M1, учитывается в counts и `salary_disclosure_rate` |
| Только `from` или только `to` | `point_estimate` = доступная граница (см. §1.4) |
| Неизвестный `gross` | консервативно трактуется как gross; помечается допущением |
| Нет курса валюты на дату | ближайший доступный курс; событие логируется |
| Грейд `unknown` | в грейдовых метриках выделяется отдельно, не смешивается с J/M/S |
| Малая выборка (n < порога) | метрика помечается флагом `low_confidence` в payload |
| Дубликаты вакансий | исключены на уровне `hh_vacancy_id` (см. [`03-data-model.md`](03-data-model.md)) |

## 5. Конфигурируемые параметры расчёта

| Параметр | Назначение | Значение по умолчанию |
|----------|------------|------------------------|
| `NDFL` | коэффициент net из gross | 0.13 |
| `base_currency` | базовая валюта | RUB |
| `default_salary_basis` | базис отображения | net |
| `outlier_method` | усечение выбросов | percentile [p1, p99] |
| `low_confidence_threshold` | мин. размер выборки | 30 |
| `percentiles` | набор перцентилей | [10, 25, 50, 75, 90] |
| `top_n_skills` | размер топа навыков | 20 |
| `top_n_employers` | размер топа работодателей | 20 |
